# 벤치마크

두 가지를 잰다.

1. **계산 정확도**(자동): 계산 툴(`verify_math`, `check_units`, `plot_function`, `render_molecule`, `plot_data`)이 까다로운 입력에 맞는 답을 내는가. 사례 414개를 기계가 판정한다. → [아래 1절](#1-계산-정확도자동)
2. **과제 비교**(사람 평가): 학생이 실제로 시키는 일(그림, 검산, 시험지, 치트시트, 슬라이드, HWP 읽기, 실험 보고서)을 openstem을 붙인 호스트와 비교 대상 서비스(2026-11-03 감사에서 정한 대상은 GPAI)가 얼마나 잘 하는가. 조교가 블라인드로 채점한다. → [아래 2절](#2-과제-비교사람-평가)

## 2. 과제 비교(사람 평가)

### 목적과 범위

같은 과제를 (A) openstem을 붙인 호스트(Claude Desktop·Claude Code 등)와 (B) 비교 대상 서비스에 시키고, 결과물의 품질·시간·실패율·재현성을 비교한다. 우열을 광고하려는 것이 아니라 **어떤 과제에서 openstem이 모자란지** 찾으려는 것이다. 결과는 점수만 저장소에 남긴다.

### 과제 세트

영역마다 10개, 모두 70개. 영역과 과제 예:

| 영역 | id 앞부분 | 과제 예 | 주로 쓰는 툴 |
|---|---|---|---|
| 그림 | `figure-` | RC 회로도, 경사면 자유물체도, 아스피린 구조식과 에스터화 반응식 | `render_tikz`, `render_molecule`, `plot_function` |
| 검산 | `verify-` | 학생 풀이(운동학, 적분, 단위)에서 틀린 줄 찾기 | `verify_math`, `check_units` |
| 시험지 | `exam-` | 단원 요약에서 객관식·서술형 시험지와 답안지 만들기 | `export_document`, 템플릿 |
| 치트시트 | `cheatsheet-` | 강의 노트 한 단원을 A4 한 쪽 치트시트로 | `export_document` |
| 슬라이드 | `slides-` | 실험 결과 5쪽 발표 자료 | `export_document`(beamer) |
| HWP 읽기 | `hwp-` | HWP 안내문·과제 공지에서 마감·제출 형식 뽑기 | `read_document` |
| 실험 보고서 | `report-` | 측정값 표 → 맞춤 그래프·불확도·보고서 | `plot_data`, `check_units`, `export_document` |

과제 설계 규칙:

- **입력 자료는 직접 만든 것만** 쓴다(아래 [주의](#주의)). 실제 강의 자료와 비슷한 난이도·분량으로 만든다.
- 과제마다 정답이나 반드시 있어야 할 요소(예: 검산 과제의 틀린 줄 번호, 회로 소자 값)를 `rubric.md`에 미리 적어 둔다. 채점 전에 바꾸지 않는다.
- 한 영역 10개 안에 쉬움 3, 보통 4, 어려움 3을 섞는다. 어려움에는 함정(무연근, 단위 섞임, 손글씨 스캔 같은 읽기 어려운 입력)을 넣는다.

### 조건 맞추기

- **기록**: 실행마다 호스트 이름·버전, 모델 이름(호스트가 보여 주는 그대로), openstem 버전, 비교 대상 서비스의 요금제·모드, 날짜·시각을 남긴다.
- **같은 날**: 한 과제의 A·B는 같은 날 돌린다(서비스·모델이 바뀌는 영향을 줄인다).
- **같은 프롬프트**: `prompt.md`를 그대로 붙여 넣는다. 첨부는 `inputs/`의 파일 그대로. 처음 답을 받은 뒤 고쳐 달라는 후속 지시는 `prompt.md`에 적힌 것만 한다(예: "그림을 PDF로 저장해 줘").
- **3회 반복**: 과제마다 A·B를 각각 새 대화에서 3번 돌린다. 앞 대화의 기억·프로젝트 설정은 끈다.
- **시간**: 프롬프트를 보낸 때부터 마지막 결과물 파일을 받은 때까지(사람이 기다린 시간 포함, 사람의 후속 입력 시간 제외).

### 평가

- **채점자**: 해당 과목 조교 2명. 둘 다 결과물이 어느 쪽에서 나왔는지 모른다(블라인드).
- **블라인드 만들기**: 실행하지 않은 제3자가 결과물 파일 이름을 무작위 코드로 바꾸고, 서비스 이름·로고·워터마크·안내 문구처럼 출처를 드러내는 부분을 가린다(내용은 고치지 않는다). 코드와 출처의 대응표는 채점이 끝날 때까지 제3자만 갖는다.
- **루브릭(0~4)**: 과제의 `rubric.md`에 항목별로 적는다. 공통 기준은 다음과 같다.

  | 점수 | 뜻 |
  |---|---|
  | 4 | 그대로 제출·사용할 수 있다 |
  | 3 | 사소한 손질(오타, 배치) 후 쓸 수 있다 |
  | 2 | 쓸 만하지만 내용 오류가 하나 있거나 중요한 요소가 빠졌다 |
  | 1 | 오류가 여럿이라 다시 만드는 편이 빠르다 |
  | 0 | 결과물이 없거나 과제와 무관하다 |

  항목은 보통 정확성(내용·계산이 맞는가), 완결성(요구한 요소가 다 있는가), 형식(제출 형식·가독성)의 셋이고, 과제 점수는 항목 평균이다.
- **채점자 사이 일치**: 두 사람의 점수가 2점 이상 다르면 둘이 근거를 보고 다시 매긴다(합의 전 점수도 남긴다). 보고서에 가중 카파(quadratic weighted κ)를 함께 적는다.
- **다른 지표**:
  - 시간: 위의 정의로 잰 초.
  - 실패율: 점수 0이거나 결과물 파일을 못 받은 실행의 비율.
  - 재현성: 같은 과제 3회의 점수 표준편차, 그리고 3회 모두 2점 이상인 과제의 비율.
- **요약**: 영역별 평균 점수(A, B, 차이와 부트스트랩 95% 구간), 시간 중앙값, 실패율, 재현성. 과제가 10개뿐이므로 영역 안의 작은 차이는 "차이 없음"으로 읽는다.

### 관리

```
benchmarks/tasks/
  <id>/                 예: figure-01-rc-circuit
    prompt.md           A·B에 그대로 보낼 지시문(한국어)
    rubric.md           항목별 0~4 기준, 반드시 있어야 할 요소
    inputs/             첨부 파일(직접 만든 것만)
  results/
    <날짜>-<평가 회차>.jsonl   점수만
```

`results/*.jsonl`은 한 줄이 한 실행·한 채점자다.

```json
{"task": "figure-01-rc-circuit", "system": "A", "run": 1, "rater": "R1", "blind_code": "K7Q2", "scores": {"accuracy": 4, "completeness": 3, "format": 4}, "seconds": 95, "failed": false, "date": "2026-11-20", "host": "Claude Desktop 1.x", "model": "(호스트 표시 그대로)", "openstem": "0.3.4", "service_plan": null}
```

결과물 파일(그림, PDF, 비교 대상 서비스의 답)은 저장소에 넣지 않는다. 평가 회차를 맡은 사람이 접근을 제한한 곳에 보관하고, 보관 위치는 저장소 밖의 평가 기록에만 적는다.

지금 있는 과제 틀(예시):

- [`figure-01-rc-circuit`](../benchmarks/tasks/figure-01-rc-circuit/): RC 회로도와 충전 곡선
- [`verify-01-kinematics`](../benchmarks/tasks/verify-01-kinematics/): 학생 풀이에서 틀린 줄 찾기
- [`cheatsheet-01-ideal-gas`](../benchmarks/tasks/cheatsheet-01-ideal-gas/): 강의 노트 → A4 한 쪽 치트시트

### 주의

- **남의 자료를 넣지 않는다**: 실제 강의 자료, 교재 문제, 기출문제, 학교 양식은 저장소에 넣지 않는다(저작권, 학교 규정). 비슷한 난이도로 직접 만든다.
- **비교 대상의 출력물을 넣지 않는다**: GPAI 등 다른 서비스의 답·그림·화면 캡처는 저장소에 넣지 않고, 점수만 남긴다. 다른 회사 서비스의 이름·로고·UI·출력물을 이 프로젝트에 가져오지 않는다는 원칙([CLAUDE.md](../CLAUDE.md))을 따른다. 이 문서에서 이름을 적는 것은 비교 대상을 밝히려는 것뿐이다.
- **자동 수집하지 않는다**: 비교 대상 서비스는 사람이 그 서비스의 화면에서 약관대로 쓴다. 스크립트·브라우저 자동화로 질의하거나 결과를 긁어 오지 않는다.
- **개인정보**: 학생 이름·학번·성적이 들어간 입력은 쓰지 않는다. 결과 jsonl의 채점자는 `R1`, `R2` 같은 코드로만 적는다.
- **공개할 때**: 결과를 밖에 알릴 때는 날짜·버전·요금제·과제 수와 함께 "이 과제 세트에서의 결과"로만 쓴다.
