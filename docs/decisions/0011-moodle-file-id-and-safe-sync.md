# 0011. Moodle 파일 id는 파일 주소로 정하고, sync는 디스크 sha256을 보고 덮어쓴다

- 상태: 채택
- 시점: 0.3.3(2026-11-03 감사 후속)

## 배경

0.3.1에서 `lms` 툴에 `sync`(과목 자료 한 번에 받기)를 더하면서, 바뀐 파일은 같은 id의 예전 사본에 덮어쓰게 했다. 2026-11-03 감사에서 두 가지가 재현됐다.

1. **파일 뒤섞임**: Moodle 파일 id가 `<모듈 id>.<contents 순번>`이었다. 교수가 같은 폴더 모듈에 파일을 하나 끼워 넣거나 지우면 순번이 밀려, 같은 id가 다른 파일을 가리켰다. 다음 sync는 "바뀐 파일"로 보고 `A.pdf` 자리에 `B.pdf`의 내용을 덮어썼다.
2. **필기본 덮어쓰기**: 학생이 받은 PDF에 필기를 하거나 내용을 고쳐도, 학교에 새 버전이 올라오면 sync가 그 파일을 그대로 덮어썼다. Windows에서 PDF 뷰어가 파일을 열고 있으면 바꾸기가 실패해 sync가 멈췄다.

둘 다 사용자 파일을 되돌릴 수 없게 잃는 문제라, `destructive_hint=False`라는 툴 주석과도 맞지 않았다.

## 결정

- **파일 id**(`src/openstem/lms/moodle.py`의 `file_key`): `<모듈 id>.<해시 15자리>`. 해시는 `fileurl`의 `/pluginfile.php/` 뒤 경로(퍼센트 인코딩을 푼 것)의 sha256 앞 12자리 16진수를 10진수로 쓴 것이다. 쿼리(`?forcedownload=1`, 토큰 등)와 `/webservice` 유무는 계산에 넣지 않는다. 같은 파일이면 목록 순서가 바뀌어도 id가 같고, 파일이 늘거나 줄어도 다른 파일로 옮겨 가지 않는다. `fileurl`이 없으면 `filepath`+`filename`으로 계산한다.
- **예전 기록 이어받기**: sync 기록 `.openstem-sync.json`을 version 2로 올렸다. 예전 형식 id(`LEGACY_ID`, `<모듈>.<순번>`)로 적힌 항목은 id로 맞추지 않고 이름별로만 모아, 이름과 sha256이 맞을 때만 이어받는다.
- **덮어쓰기 조건**(`src/openstem/tools/lms.py`의 `_store`): 바뀐 파일은 다음을 모두 만족할 때만 덮어쓴다.
  - 기록된 이름이 지금 이름이거나 sync가 붙인 ` (n)` 사본 이름이고, 그 파일이 과목 폴더 안에 있다(`_synced_path`, 기록 파일을 고쳐 폴더 밖을 가리키게 해도 따르지 않는다).
  - 디스크 파일의 sha256이 sync 기록의 sha256과 같다(받은 그대로다).
- 사용자가 고친 파일(sha256이 다름)이나 다른 앱이 열고 있어 바꿀 수 없는 파일(Windows `PermissionError`)은 그대로 두고, 새 버전을 `이름 (2)`(이미 있으면 `(3)`…)로 저장한다. 결과에 `status: new_copy`, `kept`, `why`(`edited` | `in_use`)를 싣는다.
- 세부 동작(시간·개수 상한, 실패 처리, 동시 호출 잠금)은 [lms.md](../lms.md).

## 결과

- 폴더 구성이 바뀌어도 sync가 다른 파일 내용으로 덮어쓰지 않는다. 사용자가 고친 파일과 열린 파일은 남는다. 회귀 시험은 `tests/test_lms.py`에 있다.
- 대가: 0.3.2 이하가 만든 기록의 Moodle 파일은 한 번은 이름·sha256으로 다시 맞춘다. 이름이 바뀐 파일은 이어받지 못해 새로 받는다.
- 대가: 사용자가 고친 파일이 있으면 과목 폴더에 `이름 (2)` 사본이 쌓인다. 어느 쪽을 남길지는 사용자가 정한다.
- 대가: 교수가 파일 주소(폴더 경로나 파일 이름)를 바꾸면 같은 자료라도 새 id가 되어 새 파일로 받는다.
- Canvas 파일 id는 LMS가 주는 고정 id라 이 문제가 없었다. 덮어쓰기 조건은 Canvas에도 똑같이 쓴다.
