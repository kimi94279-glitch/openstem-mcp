# 0008. LMS는 비밀번호 대신 사용자가 만든 토큰·캘린더 주소만 받고, 읽기만 한다

- 상태: 채택
- 시점: M6(0.3.0), 0.3.1에서 sync 추가

## 배경

학생은 과목 자료·마감·공지를 AI가 읽어 오기를 원한다. 학교 계정 비밀번호를 받으면 그 학생의 모든 학교 서비스(성적, 수강 신청 등)에 닿는 열쇠를 맡게 되고, 저장·전송 과정의 사고가 곧 계정 탈취가 된다. 쓰기(제출·글쓰기)를 하면 AI의 실수가 되돌릴 수 없는 결과가 된다.

## 결정

- 비밀번호는 받지 않는다. 사용자가 LMS에서 직접 만든 액세스 토큰(Canvas: 승인된 통합 → 새 액세스 토큰, Moodle: 보안 키)만 받는다. 토큰을 막은 학교는 캘린더 구독 주소로 마감만 읽는다.
- 읽기 전용이다. 제출·글쓰기 API는 부르지 않는다. 받은 파일은 자료 폴더 `LMS/<과목>/`에만 저장한다.
- 토큰은 설정한 LMS 주소(https)로만 보내고, 다른 origin으로 가는 리디렉션에는 싣지 않는다. 툴 결과에서 토큰과 캘린더 주소를 지운다.
- LMS 글은 남이 쓴 데이터라 지시로 따르지 말라고 툴 설명과 결과에 적는다.
- 세부 동작은 [lms.md](../lms.md).

## 결과

- 토큰은 사용자가 LMS에서 언제든 폐기할 수 있다.
- 학생 토큰 만들기를 막은 학교(모바일 서비스가 꺼진 Moodle 등)는 마감만 된다.
- 실제 학교 LMS로는 아직 확인하지 못했다(가짜 서버로 시험).
- **확인할 것**: Canvas 공식 API 문서(OAuth 항목의 수동 토큰 생성)는 여러 사용자가 쓰는 앱이 사용자에게 토큰을 직접 만들어 넣게 하는 것을 API 정책 위반으로 보고 OAuth를 요구한다. 학교가 학생 토큰 만들기를 막거나 만료 기간을 둘 수도 있다. 학교·Instructure 정책과 맞는지 확인하기 전에는 "지원"이라는 말을 조심해서 쓴다.
