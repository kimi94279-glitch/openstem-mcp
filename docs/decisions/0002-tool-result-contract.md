# 0002. 툴은 MCP를 모르고, LLM이 고칠 수 있는 결과를 돌려준다

- 상태: 채택
- 시점: M1, mcp 2.x 이전 뒤 정리

## 배경

호스트 LLM은 결과 파일을 직접 볼 수 없다. 긴 컴파일 로그를 통째로 받으면 원인을 찾지 못하고 문맥만 낭비한다. 또 툴 구현이 MCP 타입에 묶이면 SDK가 바뀔 때마다(mcp 2.x에서 FastMCP가 `MCPServer`로 이름이 바뀌었다) 모든 툴을 고쳐야 한다.

## 결정

- 툴 구현(`tools/*.py`)은 `ToolResult`(ok, data, preview_png, more_images)만 돌려준다. MCP 변환은 `server.py`의 `_to_mcp` 한 곳에서 한다: 텍스트 JSON + PNG 이미지, 실패면 `is_error`.
- 성공하면 파일 경로와 미리보기 PNG를 준다. 실패하면 짧고 구체적인 에러(줄 번호 포함, 최대 10줄)를 준다. TeX 에러는 로그에서 `!` 줄과 `l.<번호>` 줄만 뽑고, 줄 번호는 사용자가 보낸 code 기준으로 바꾼다.
- 툴 설명에는 언제 쓰는지, JSON 입력 예시 1개, `On failure:` 줄을 꼭 넣는다(`tests/test_server.py`가 확인).

## 결과

- LLM이 미리보기를 보고 고치는 반복(최대 3회)이 가능하다(`figure` 프롬프트).
- SDK를 바꿔도 `server.py`만 고치면 된다.
- 이미지 결과를 모델에 넘기지 못하는 호스트에서는 미리보기 확인 단계가 빠진다.
