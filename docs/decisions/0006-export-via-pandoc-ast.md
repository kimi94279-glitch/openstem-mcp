# 0006. export_document는 정규식이 아니라 pandoc 문서 구조로 검사한다

- 상태: 채택(정규식 방식을 대체)
- 시점: M4, 2026-11 점검 뒤

## 배경

처음에는 마크다운에서 정규식으로 그림을 찾아 경로를 검사했다. 점검에서 참조식 그림(`![a][r]`), 중첩 대괄호, 앞 공백으로 검사가 우회되고, pandoc이 URL 그림을 실제로 요청하는 것을 재현했다. 정규식이 아주 느려지는 입력도 있었다.

## 결정

1. pandoc으로 마크다운을 먼저 문서 구조(JSON)로 읽는다(`--sandbox`, 입력 형식 `markdown-raw_tex-raw_html-raw_attribute-yaml_metadata_block`). 마크다운 속 `\명령`은 글자로 나오고, YAML 머리말로 제목에 수식을 넣는 길도 막힌다.
2. 구조 안의 모든 `Math`(texcheck + 중괄호 짝)와 `Image`(결과물 폴더 안 파일만, URL·`data:` 등 거절)를 검사하고, raw 블록은 거절한다. 어떤 문법으로 쓴 그림이든 구조에서는 다 보인다.
3. 검사를 마친 구조를 docx·pptx나 LaTeX로 바꾼다. 배치(시험지·카드·치트시트)는 Lua 필터가 만들고, 규칙 위반은 파이썬이 구조를 보고 먼저 짧은 에러로 돌려준다.

## 결과

- 그림 경로 우회와 URL 요청이 막혔다. 같은 검사가 pptx에도 적용된다.
- pandoc을 두 번 부른다(구조 읽기, 출력). PDF는 한 번만 컴파일한다(`reruns=0`).
